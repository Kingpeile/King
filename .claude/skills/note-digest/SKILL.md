# Note Digest — 每周笔记总结报告

只认一个文件夹：**`笔记同步助手/`**（用户 Obsidian 里所有同步来的笔记都在这，按日期命名）。
产出也只放回这个文件夹。这是用户自己的 loop engineering 循环之一。

## 这个循环要回答的问题

> 这一周新记的东西，跟我过去记的，有哪些**重合**（又在关注同一件事）、
> 哪些**递进**（把旧想法往前推了一步）？

## 铁律

- `笔记同步助手/` 里**已有的笔记只读，绝不改写或删除**。
- 你唯一**写**的，是每周一份总结报告：`笔记同步助手/_周总结-<本周结束日期>.md`
  （下划线开头，在 Obsidian 里排最前，和日期笔记区分开）。
- 不在别处建文件夹，不碰 app 代码（`miniprogram/`、`webapp/`）。

## 一轮怎么走

1. **发现**
   - 「本周新增」：`笔记同步助手/` 里日期落在本周的笔记（看文件名日期或 frontmatter `date`）。
   - 「过去已存」：该文件夹里更早的笔记。

2. **生成报告**：对本周每条新增，去过去的笔记里找相关的（按标签、关键词、主题、书名/人名），
   判断关系，按下面模板写进报告：
   - **🔁 重合**：本周和过去在讲同一主题 / 反复出现的关注点。
   - **📈 递进**：本周深化、补充、或推进了过去某条的想法。

3. **验证（别硬凑关系）**：报告写完回头核对——引用的历史笔记是否真实存在？
   说的「重合 / 递进」是不是真有其事，还是为凑数硬扯？**不确定的关系宁可不写。**
   （这是循环里那个「能说不」的步骤，整理的价值在于真实，不是堆数量。）

4. **持久化**：报告存进 `笔记同步助手/`。本周若已有同名报告，覆盖更新。

## 报告模板

```markdown
---
title: "周总结 <本周结束日期>"
type: weekly-summary
generated: <YYYY-MM-DD>
---

# 📊 周总结（<起> – <止>）

## 本周新增
- [[<日期/标题>]] — 一句话

## 和过去的呼应

### 🔁 重合 / 又在关注的
- 本周 [[A]] 与过去 [[B]]：都在讲 <主题>。<一句点出重合点>

### 📈 递进 / 往前推了一步
- 本周 [[C]] 把过去 [[D]] 的想法推进了：<具体怎么深化 / 补充的>

## 信号
- 这周反复出现的关注点：<…>
- 值得深入的方向：<…>
```

## 边界

- **看不到 `笔记同步助手/` 文件夹时**（比如在没同步笔记的云端环境里跑），
  明确告诉用户「这里看不到你的笔记，请在本地 Obsidian 跑」，**不要对着空文件夹硬造报告**。
