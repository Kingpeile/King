做我的「本周周报」,回答一个问题：**这周我干了什么。**
把我这台机器上本周的活动，揉成一份报告。

## 数据源（都在本地，全部只读，绝不改/删原文件）

1. **Codex 会话（轻量优先）**:**只读** `~/.codex/memories/rollout_summaries/` 里本周日期的 `*.md` 摘要——
   这些是现成短摘要，直接用。**不要去读** `~/.codex/sessions/` 的完整 `*.jsonl`(太大、太慢、会拖垮整轮)。
2. **Claude Code 终端会话（只取意图）**:`~/.claude/projects/` 下本周修改过的 `*.jsonl`——
   **每个会话只看开头我的第一条提问 + 大致结论**,知道我在干嘛就够，**别读整段对话**。
   会话多时只取最近 8 个，其余只按文件名/时间列一句带过。
3. **笔记**：`笔记同步助手/` 下本周新增的笔记
4. **（可选投递口）**`笔记同步助手/_聊天/` 下本周任何对话文件——有就读，没有就跳过。
   留给以后手动丢进来的飞书 / Hermes 对话；现在通常是空的，空就别提。

> 不接 Hermes 桌面壳的内部缓存（Electron 的 Local Storage/IndexedDB），格式不可靠、也抓不到飞书端的使用。Hermes 的内容以后只从上面第 4 项的投递口进。

## 无人值守铁律（这是 loop，没人盯着）

- **不准问问题**:遇到要选择/拿不准的地方，自己判断决定，**绝不调用 AskUserQuestion 停下来等我**。停下来 = loop 卡死。
- **一轮要短，目标几分钟内跑完**:跑太久会在代理网络上断线（ECONNRESET）。靠「少读」实现——见上面数据源的轻量规则，能用现成摘要就别读原文。
- **本周报告已存在就直接覆盖更新那一篇**,别跳过、也别新建重复文件。
- 遇到网络错误，只**重试当前这一个文件**,别整轮从头重来。

## 铁律

- 所有源**只读**。唯一要**写**的，是这份周报，存到**库根目录的 `周报/` 文件夹**:
  `周报/周报 <起> 至 <止>.md`(沿用我现有的命名「周报 起 至 止」,无缝替代我手动贴的那份）。
  注意：是库**根目录**那个 `周报/`(和「笔记同步助手」「工作文档」并列),不是笔记同步助手里面。
- **格式对齐往期**:动笔前先看 `周报/` 文件夹里**最近一篇往期周报**,照它的小标题、结构、语气写，
  保持一致。往期长啥样、新的就长啥样。`周报/` 里没有往期时，才用本文末尾的兜底模板。
- **绝不一次把原始 `.jsonl` 全读进来**——那会触发长上下文报错、又慢又卡。必须分步压缩（见下）。

## 怎么走（分步，这是防上下文爆炸的关键，别跳）

1. **定窗口**：本周 = 最近 7 天（`<起>` 到 `<止>`,以今天为止往前 7 天）。

2. **逐源逐文件压成短摘要**——**一次只读一个文件**,读完写 3–5 行摘要到
   `周报/_缓存/<源>-<文件名>.md`,然后**丢掉原文再读下一个**。
   绝不同时把多个原始会话抱在手里。每条摘要只记：
   - 这次聊/做了什么主题
   - 有什么决定、产出、进展
   - 有什么没解决、待办

3. **合成**：所有源压完后，**只读这些短摘要 + 本周新笔记**,合成周报，
   并**对齐 `周报/` 里最近一篇往期的格式**。

   其中「本周阅读地图」这一节**必须做成『诊断』,不是把笔记分堆罗列**——做满下面三件事：
   - **连到过去**:本周每条主线，去 `笔记同步助手/` 里找它延续/呼应的旧笔记
     （只看旧笔记的文件名/标题/标签判断相关，别批量读正文，只对最相关的一两条翻正文确认）。
     用 `[[精确文件名]]` 双链把「本周这篇 ←→ 过去那篇」连起来、标日期，让我看出这条线追了多久。
   - **进展阶段老实说**:每条线现在在「囤资料 / 看懂了 / 动手实践 / 产出了东西」哪个阶段，
     有依据地判断，**该降级就降级**（连读几周观点却没改变行为，不算「看懂」,算「囤资料」）。
     零产出的线直接标明，别都夸成在推进。
   - **卡点与下一步**:挑出**横跨多条线的共同模式/毛病**(这是最有价值的洞察）;指出盲区
     （反复碰却始终没真正深入的角）;给**一个最具体、可执行的下一步**(读什么 / 做什么能把某条线推一格），
     优先「把已有的跑通」而不是「再上新工具」。

4. **核对**：说的事是不是真有其事?引用的旧笔记/会话是否真实存在?进展阶段和卡点是否有依据?
   不确定的不写、不硬判，别硬凑。

5. **清场**：写完把 `周报/_缓存/` 删掉（临时文件，不留）。

## 兜底模板（仅当 `周报/` 里没有往期周报可参照时才用；有往期就照往期来）

```markdown
# 周报 <起> 至 <止>

## 这周我干了什么（按事/项目归类，跨工具）
- <一件事>:在 Claude Code / Codex 里聊了/做了…，进展到…
- <另一件事>:…

## 聊得最多的几件事
- <主题>:反复出现，主要在 <哪个工具> 里推进

## 本周阅读地图 & 进展诊断（做成诊断，不是罗列）
### 我在追的几条线（连到过去）
- **<主线名>**:本周 [[新笔记]] 延续/推进了 [[旧笔记]]（起于 <日期>,已追 <N> 周）。
  - 🔁/📈：这条线具体怎么连的、推进到哪了
  - 进展阶段：囤资料 / 看懂了 / 动手实践 / 产出了东西（老实判，该降级就降级）
### 卡点与下一步
- 共同模式：<横跨多条线的同一个毛病——最有价值的那条>
- 盲区：<反复碰却始终没真正深入的角>
- 最具体的下一步：<读什么 / 做什么，能把某条线推一格；优先跑通已有的，别再上新工具>

## 没干完 / 下周接着
- <待办、悬着的事>

## 信号
- 这周我主要的注意力花在了：<…>
```
（提到笔记一律用 `[[精确文件名]]` 双链，文件名照实际的写，点不进去的死链不要。）

## 边界

- 某个源这周没内容 → 跳过，写一句「本周无」,别硬编。
- 某个路径看不到（比如这台没装 Codex / 没有 `_聊天/` 文件夹）→ 跳过那一项，别报错停住。
- 看不到 `笔记同步助手/` → 直接说「这里看不到你的笔记」,别凭空造报告。
