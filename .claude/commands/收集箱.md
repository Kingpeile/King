帮我消化收集箱，治我「囤资料、收藏即心安、然后再也不看」的毛病。

## 数据源（只读，绝不改/删原文件）

- **收集箱**：`Clippings/` 下**自上次消化以来新增**的笔记（看文件名日期或 frontmatter `date`/`created`;
  上次消化清单 `Clippings/_消化清单.md` 的生成时间之后的，算新增）。
- 看不到 `Clippings/` 就直接说，别凭空编。

## 无人值守铁律

- 不准问问题，自己判断决定，绝不调用 AskUserQuestion 停下等我。
- 一轮要短：新收藏**一条只读标题 + 开头几句**判断主题，别逐篇精读全文。多的话只挑最近 30 条。
- 原文只读。唯一写的是消化清单（见下）。

## 怎么走

1. 列出自上次以来的新收藏，每条用 `[[精确文件名]]` 双链 + 一句话它在讲什么。
2. **按主题归类**(跟我现有的关注线对齐：Obsidian+AI、Claude Code、MiniMax、健康…），相近的并一起。
3. **最关键一步——分两堆,别和稀泥**:
   - 🔨 **值得真动手**:这条不是看看就完，是该照着做点什么 / 该并进某条在追的线。
     **每条配一个具体动作**(读完做什么、跟哪条线接上）。这堆控制在 ≤5 条，宁缺毋滥。
   - 📦 **只是囤着**:有用但当下不必动，归档心里有数就行。**老实归这堆，别为了好看硬塞进上一堆。**
4. 给一句**收藏体检**:这阵子我老在囤哪类东西却不动手?有没有囤了很久该清理/该做的?

## 输出

写到 `Clippings/_消化清单.md`(**覆盖更新**同一份，下划线开头排最前，当作一个活的待办短清单）。

```markdown
# 📥 收集箱消化（更新于 <YYYY-MM-DD>）

## 🔨 值得真动手（≤5 条，配动作）
- [[新收藏]] — <讲什么> → **动作**:<具体做什么 / 接到哪条线>

## 📦 只是囤着（归档心里有数）
- [[新收藏]] — <一句话>

## 体检
- 这阵子老在囤的：<…>
- 囤太久该清/该做的：<…>
```

## 边界

- 没有新收藏 → 写一句「自上次以来没有新收藏」,别硬造。
- 看不到 `Clippings/` → 直接说，别编。
